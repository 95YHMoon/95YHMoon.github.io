## 수작업 입력 자동화

창고에 입고되는 물품에는 품명, 수량, 입고일, 입고 번호 등이 적힌 종이 라벨이 붙는다. 기존에는 작업자가 이를 눈으로 보고 수기 입력했으나, 물량이 많아질수록 오입력과 작업 지연이 발생했다.

목표는 **라벨 사진을 입력하면 구조화된 JSON 데이터를 출력하는 자동화 파이프라인 구축**.

```json
{
  "item_name": "플라스틱연필꽂이",
  "sub_name": "분홍색 (낱개포장)",
  "quantity": "200",
  "inbound_date": "2025-06-28",
  "inbound_no": "20"
}
```

## 단일 OCR 모델의 한계

초기에는 PaddleOCR을 적용해 텍스트를 검출하고 인식했다. 텍스트 추출 자체는 잘 되었으나, 뽑힌 결과는 단순 텍스트 덩어리였다. 이를 '품명', '수량' 등의 필드로 분류하기 위해 정규표현식 후처리가 필요했다.

그러나 현장 라벨은 양식이 일정하지 않았다.
- 품명이 두 줄로 기재된 경우
- 부자재 설명이 괄호 형태로 들어간 경우
- 입고 번호 형식이 `20`, `RR-5`, `1-9` 등 제각각인 경우

정규식 규칙을 추가할 때마다 다른 라벨 양식에서 파싱 에러가 발생했다. 이에 규칙 기반 후처리 방식 대신, **이미지에서 구조화된 JSON을 직접 생성하는 End-to-End 모델**로 전환하기로 했다.

## Donut 모델 도입

대안으로 OCR-free 구조인 [Donut](https://github.com/clovaai/donut)을 선택했다. Donut은 텍스트 영역 검출과 인식 단계를 거치지 않고, 이미지를 입력받아 시퀀스 형태로 구조화된 JSON을 직접 생성한다. 이를 통해 정규식 후처리 파이프라인을 제거할 수 있었다.

## 파이프라인 분할 설계

촬영된 사진을 Donut에 바로 입력하기는 어렵다. 실제 현장 사진은 복잡한 배경(박스, 바닥 등)을 포함하며, 라벨이 비스듬히 붙어 있어 Donut이 관심 영역(ROI)을 제대로 포착하지 못한다.

따라서 라벨 영역을 잘라내고 정방향으로 펴주는 전처리 모듈을 추가하여 파이프라인을 3단계로 구성했다.

```
![라벨 검출](2025-09-23-label-pipeline-1_yolo01.jpg)
_라벨 검출 예시_

→ ① 라벨 검출 (YOLO-OBB)
→ ② 크롭 및 평탄화 (Perspective Transform)
→ ③ 구조화 추출 (Donut)
```

1. **라벨 검출 (YOLO-OBB)**: 기울어진 라벨 위치를 찾기 위해 회전 바운딩 박스(OBB) 모델을 사용한다.
2. **크롭 및 평탄화**: 검출된 4개 꼭짓점 좌표를 기준을 라벨 영역만 자르고 투영 변환하여 반듯한 직사각형으로 펴준다.
3. **구조화 추출**: 정방향 라벨 이미지를 Donut에 넣어 JSON을 생성한다.

## 파이프라인 분할 이유

단일 모델 대신 모듈형 파이프라인을 구성한 이유는 오류 추적과 디버깅 때문이다. 파이프라인을 단계별로 나누면 출력 오답이 발생했을 때 라벨 검출(①), 영역 추출 및 평탄화(②), Donut 인식(③) 중 어느 모듈에서 문제가 생겼는지 명확히 격리하여 파악할 수 있다.
