이미지 매칭 파이프라인을 구축하면서 반복적인 수작업 구간이 발생했다. 신규 데이터 수집, 매칭 스크립트 실행, 결과 검증, 알림 발송으로 이어지는 과정을 매번 터미널에서 순차적으로 실행해야 했다. 이러한 "트리거 → 실행 → 후속 처리" 오케스트레이션을 자동화하기 위해 n8n 도입을 검토했다.

## n8n의 역할과 특징

n8n은 노드 기반 오픈소스 워크플로우 자동화 도구다. Zapier, Make와 유사한 카테고리에 속하지만, 자체 서버에 셀프 호스팅하여 운영할 수 있다는 차이점이 있다.

워크플로우 구성 요소는 세 가지로 나뉜다.

- **트리거 노드**: 워크플로우 실행 시점 지정 (WebHook, Cron, 폴더 변경 감지 등)
- **액션 노드**: 작업 수행 (HTTP 요청, DB Query, 파일 처리, 메시지 발송 등)
- **로직 노드**: 조건 분기(If/Switch) 및 데이터 변환

노드 간에는 JSON 데이터 패킷이 전달되며, 대부분의 노드는 배열 입력에 대해 자동으로 반복 실행을 지원하므로 코드 수준의 명시적 반복문 작성을 줄일 수 있다.

## 코드와의 역할 분담

n8n은 연산 처리 자체보다는 흐름을 제어하는 오케스트레이션 계층에 적합하다. 이미지 지각 해시(Perceptual Hash) 계산이나 임베딩 생성과 같은 무거운 연산 작업은 기존 Python 환경에서 처리하고, n8n은 그 앞뒤 흐름을 연결한다.

- **Code 노드**: 워크플로우 내에서 인라인 JavaScript/Python 스크립트 실행
- **HTTP Request 노드**: 외부 API 및 자체 구축 API 호출
- **Execute Command 노드**: 셀프 호스팅 환경에서 서버 셸 명령 직접 실행

"무엇을 언제 실행하고, 결과를 어디로 전달할지" 관리하는 접착제(Glue) 역할을 수행한다.

## 이미지 매칭 파이프라인 적용 구조

자사몰과 협력몰 간 동일 상품 이미지를 찾아내는 기존 매칭 시스템에 n8n을 적용할 경우 다음과 같이 자동화 구간을 정의할 수 있다.

1. **신규 데이터 감지 및 스크립트 트리거**: 신규 이미지 데이터 도착을 감지하여 매칭 스크립트를 자동 실행하고, 신규 확정 건수와 검수 대기 건수를 정리하여 담당자에게 알림을 발송한다.
2. **리뷰 결과 후속 처리**: 사람이 직접 수행하는 최종 이미지 검수 단계는 제외하되, 검수 완료 파일이 갱신될 때마다 대시보드 및 공유 문서에 최종 수치를 반영하는 작업은 자동화한다.
3. **인프라 모니터링**: 데이터베이스, Vector DB, 검색 엔진 컨테이너 상태를 주기적으로 헬스체크하고 예외 발생 시 알림을 전송한다.

## 다중 서비스 엔드포인트 관리 (Reverse Proxy)

n8n을 기존 인프라에 추가하면 관리해야 할 컨테이너 포트가 늘어난다. 검색 엔진, DB, 대시보드, n8n 등이 각기 다른 포트를 사용할 경우 외부 노출 및 포트 관리가 번거로워진다.

이를 해결하기 위해 리버스 프록시(Reverse Proxy)를 도입하여 단일 진입점으로 통합 관리하는 구조가 권장된다.

```
외부 요청 ──▶ 프록시 (Port 80/443)
│
┌───────────┼───────────┐
▼           ▼           ▼
대시보드      n8n        검색엔진
(내부 전용)  (내부 전용)   (내부 전용)
```

웹 기반 서비스를 제외한 DB 등의 서비스는 내부 네트워크(`bridge` 또는 전용 `net`) 안에서만 통신하도록 제한하고 외부 포트 노출을 차단한다. 프록시 도구로는 Traefik을 적용하면 라벨 기반 서비스 자동 감지가 가능하여 모듈 추가 시 설정 부담을 줄일 수 있다.

## 정리

n8n은 연산 자체를 대체하는 도구가 아니라, 기존 스크립트와 서비스를 연결하는 오케스트레이터다. 반복적인 실행 및 알림 흐름을 자동화하고, 리버스 프록시 구조를 함께 적용하면 파이프라인 관리 효율을 높일 수 있다.
