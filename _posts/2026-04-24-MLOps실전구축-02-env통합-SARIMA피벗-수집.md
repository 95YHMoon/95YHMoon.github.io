## 1. `.env`를 하나로 통합

원래는 성격이 다르다는 이유로 `.env`를 둘로 나눠뒀었다. 하나는 로컬 컨테이너용 일회성 개발 비밀값(postgres 계정), 다른 하나는 외부 시스템에 대한 장기 유효 비밀값(ERP API 인증정보). 논리는 그럴듯했다. 그런데 막상 관리하다 보니 "어디에 뭐가 있더라"를 매번 떠올려야 해서 오히려 더 헷갈렸다. 그래서 그냥 합쳤다.

실제 값은 프로젝트 루트의 `.env` 한 곳에만 두고, 변수는 접두어(`ECOUNT_*`, `POSTGRES_*`)로 구분했다. 두 가지 덕에 코드는 한 줄도 안 고치고 파일 배치만 바꿔서 끝났다.

- docker compose는 실행 디렉토리에서 `.env`를 찾는다. 그래서 하위 디렉토리의 `.env`를 루트 파일을 가리키는 심볼릭 링크로 바꿨다. 실제로는 파일 하나를 유지하면서 compose의 기본 동작도 그대로 살린 셈이다.
- 파이썬 쪽 `load_dotenv()`는 상위 디렉토리까지 훑어 `.env`를 찾는다. 그래서 하위 폴더에 파일이 없어도 루트의 것을 알아서 집는다.

## 2. 학습 대상을 Transformer → SARIMA로

1편에서는 기존 Transformer(멀티헤드 어텐션 + month embedding)를 학습 단계 대상으로 잡았었다. 그런데 저장소를 다시 뒤져보니, 정작 그 Transformer 결과가 잘 안 나와서 이미 SARIMA를 베이스로 골라뒀던 흔적이 여기저기 있었다. 같은 데이터로 스텝별 정상성 검정·차분·AIC 비교까지 마친 R 스크립트가 있었고, 파이썬 쪽에도 `pmdarima.auto_arima` 자동 차수 탐색과 수동 지정을 둘 다 지원하는, 꽤 잘 만들어진 `SARIMAModel` 래퍼가 이미 있었다.

그래서 계획을 바꿨다. Transformer를 새로 포팅하는 대신 이미 있는 `SARIMAModel`을 재사용하기로 했다. 다만 이 파일을 통째로 import하면 비교용 무거운 의존성(torch, prophet 등)이 딸려오기 때문에, 필요한 클래스만 뽑아 별도 모듈로 분리했다. auto_arima 모드로 스모크 테스트까지 통과했다.

```python
m = SARIMAModel()      # order=None → auto_arima 모드
m.fit(series)
print(m.order_str)     # 예: ARIMA(0,1,1)(2,0,1)[12] [auto]
print(m.predict(6))    # 6개월 예측
```

이 피벗 덕에 `pipeline` 이미지도 한결 가벼워졌다. TensorFlow 계열 없이 statsmodels + pmdarima + 표준 데이터 스택이면 된다. (statsmodels는 특정 버전에서 최신 scipy와 임포트 충돌이 있어서, 로컬에서 검증된 조합으로 고정하는 정도의 손질만 필요했다.) 이 이미지로 실제 run을 찍어서, postgres에 파라미터·메트릭이 남는지, 아티팩트 프록시 업로드가 되는지까지 확인했다.

## 3. 수집 단계 (`collect.py`)

ERP에 매출 이력 조회 API가 없다는 건 1편에서 이미 확인했다. 원본은 여전히 사람이 수동 export한 엑셀이고, 앞으로 Airflow가 이걸 갱신할 예정이긴 한데 최종 형태(엑셀 갱신이냐 CSV냐 DB 적재냐)는 아직 정하지 않았다.

그래서 수집 단계를 "원본이 뭐가 됐든 검증하고 스냅샷을 뜨는 스크립트"로 정의하고, 원본 경로는 `--source` 인자로 받게 했다. 나중에 산출물 형식이 바뀌어도 스크립트 자체는 안 건드리게 하려는 것이다. 검증 로직은 다음 단계인 전처리가 실제로 기대하는 구조(연도별 시트, 시트마다 다른 위치의 항목·수량 컬럼, 타깃 품목 존재 여부)를 그대로 근거로 삼았다.

### 트러블슈팅: 바인드 마운트에서 원본 읽기 실패

처음 돌렸을 때 원본을 여는 순간 리소스 데드락 계열 에러가 났다. 순수 바이너리 읽기로도 재현됐고 다른 엑셀에서도 똑같았는데, 이상하게 컨테이너 안에서 새로 만들거나 복사한 파일은 같은 경로에서도 멀쩡히 읽혔다. macOS Docker Desktop의 파일 공유 계층이 마운트된 원본을 큰 덩어리로 직접 read할 때 생기는 알려진 버그로 보인다.

해결은 어이없을 만큼 간단했다. 순서를 "원본을 직접 검증"에서 "먼저 스냅샷으로 복사하고, 그 복사본을 검증"으로 바꿨더니 그냥 됐다.

```python
def main() -> None:
    ...
    dest = snapshot(args.source, args.raw_dir)  # 먼저 복사
    validate(dest)                               # 복사본을 검증
```
