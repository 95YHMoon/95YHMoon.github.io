파이프라인 각 모듈을 구축하는 과정에서 발생한 데이터 문제와 해결 방식을 정리한다.

## 합성 데이터 생성

초기에는 라벨 사진과 정답 JSON 데이터셋이 없었다. 현장 수집 및 라벨링 비용을 줄이기 위해 [SynthDoG](https://github.com/clovaai/donut) 방식으로 합성 데이터를 생성했다.

랜덤 텍스트 기반으로 라벨 이미지를 렌더링하고, 실제 환경 노이즈를 반영하기 위한 증강을 적용했다.
- **종이 구김**: Delaunay 메쉬 변형으로 라벨 질감 모사
- **조명 반영**: 배경 이미지 밝기에 맞춘 명암 조정
- **노이즈**: 모션 블러, 가우시안 노이즈, JPEG 압축 적용

이를 통해 학습용 합성 데이터 1,000장을 생성했다.

## Sim2Real Gap 문제 해결

합성 데이터로 검출 모델(YOLO-OBB)을 학습시켰을 때 검증 mAP는 0.995였다. 그러나 이 수치는 합성 데이터셋 내부 평가 결과일 뿐이었다. 실제 현장 사진에 적용하자 조명, 각도, 배경 복잡도 차이로 인해 검출 성능이 하락했다.

이를 해결하기 위해 실제 현장 사진 100장을 수집 및 라벨링하여 합성 데이터셋에 섞어 재학습시켰다. 소량의 실제 데이터 추가만으로도 도메인 간 격차가 크게 완화되었다.

> **참고**: 실제 라벨 좌표 일부가 정규화 범위(`1.0`)를 미세하게 초과(`1.012` 등)하여 데이터 로더에서 유실되던 현상이 있었다. Coordinate Clipping(`0.0 ~ 1.0`) 처리를 통해 해당 데이터를 정상 복구했다.

## 방향 보정(Orientation) 및 좌표 정렬

라벨 검출 후 크롭된 이미지에서 방향 박리와 거울상 반전 현상이 발생했다.

### 1. 거울상 반전 이슈
크롭 결과가 좌우 반전되는 현상이 나타났다. 합성 데이터 생성 코드와 실제 라벨링 툴 간의 꼭짓점 좌표 생성 순서가 달랐기 때문이다.
Perspective Transform 적용 전, 4개 꼭짓점 중 가장 좌상단에 가까운 점을 기준으로 좌표 순서를 매번 자동 재정렬하도록 전처리 로직을 수정하여 해결했다.

### 2. 180도 회전 탐지 실패
YOLO-OBB는 사각형의 영역만 검출할 뿐, 텍스트의 상하 방향은 구분하지 못한다. 이를 위해 4방향(0°, 90°, 180°, 270°) 회전 분류 모델(ResNet18)을 추가했다.

그러나 모델이 90°/270°는 구분하면서 180° 반전 이미지는 0°로 잘못 예측했다. 원인은 학습 데이터의 클래스 불균형이었다.

```
0도: 44장  |  90도: 21장  |  180도: 7장  |  270도: 28장
```

180도 데이터가 7장에 불과해 모델이 180도를 0도로 오분류하는 편향이 발생했다. 각 방향별 데이터를 회전 증강하여 100장씩 균등하게 맞춘 뒤 재학습시켜 문제를 해결했다.

## 정리

발생한 문제들의 원인은 알고리즘보다 데이터 분포와 형식에 있었다.
- 합성 데이터 mAP 착시 -> 실제 데이터 혼합으로 해결
- 거울상 반전 -> 꼭짓점 좌표 정렬 로직 추가
- 180도 회전 오분류 -> 데이터 불균형 해소

다음 편에서는 전체 파이프라인의 평가 결과와 지표 해석 방식을 다룬다.

> **요약**
> - SynthDoG 기반 합성 데이터 1,000장 생성 및 노이즈 증강 적용
> - mAP 착시(Sim2Real Gap)를 실제 데이터 100장 혼합 학습으로 해결
> - 좌표 재정렬 로직으로 거울상 반전 해결, 클래스 불균형 해소로 180도 회전 분류 성능 개선
