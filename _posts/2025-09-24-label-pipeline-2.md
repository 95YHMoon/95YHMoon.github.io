파이프라인 각 모듈을 구축하는 과정에서 발생한 데이터 문제와 해결 방식을 정리한다.

## 합성 데이터 생성

초기에는 라벨 사진과 정답 JSON 데이터셋이 없었다. 현장 수집 및 라벨링 비용을 줄이기 위해 [SynthDoG](https://github.com/clovaai/donut) 방식으로 합성 데이터를 생성했다.

랜덤 텍스트 기반으로 라벨 이미지를 렌더링하고, 실제 환경 노이즈를 반영하기 위한 증강을 적용했다.
- **종이 구김**: Delaunay 메쉬 변형으로 라벨 질감 모사
- **조명 반영**: 배경 이미지 밝기에 맞춘 명암 조정
- **노이즈**: 모션 블러, 가우시안 노이즈, JPEG 압축 적용

이를 통해 학습용 합성 데이터 1,000장을 생성했다.

## Sim2Real Gap 문제 해결

합성 데이터로 검출 모델(YOLO-OBB)을 학습시켰을 때 검증 mAP는 0.995였다. 그러나 이 수치는 합성 데이터셋 내부 평가 결과일 뿐이었다. 실제 현장 사진에 적용하자 조명, 각도, 배경 복잡도 차이로 인해 검출 성능이 하락했다.

이를 해결하기 위해 실제 현장 사진 100장을 수집 및 라벨링하여 합성 데이터셋에 섞어 재학습시켰다. 소량의 실제 데이터 추가만으로도 도메인 간 격차가 크게 완화되었다.

> **참고**: 실제 라벨 좌표 일부가 정규화 범위(`1.0`)를 미세하게 초과(`1.012` 등)하여 데이터 로더에서 유실되던 현상이 있었다. Coordinate Clipping(`0.0 ~ 1.0`) 처리를 통해 해당 데이터를 정상 복구했다.

## 투영 변환 및 꼭짓점 좌표 정렬

별도의 방향 분류 모델을 두는 대신, YOLO-OBB가 검출한 4개 꼭짓점 좌표를 기하학적으로 정렬하여 Perspective Transform(투영 변환)을 적용하는 전처리 로직을 구축했다.

이 과정에서 두 가지 문제가 발생했다.

### 1. 꼭짓점 좌표 순서 불일치로 인한 거울상 반전
크롭 결과가 좌우 반전되는 현상이 발생했다. 합성 데이터 생성 코드와 실제 라벨링 툴 간 꼭짓점 좌표 저장 순서가 달랐기 때문이다.
- 합성 데이터: `[좌상, 우상, 우하, 좌하]` 순서로 생성
- 실제 라벨링 툴: 기하학적 임의 순서로 좌표 기록

Perspective Transform 적용 전, 4개 꼭짓점 중 가장 좌상단에 가까운 점을 기준으로 좌표 순서를 자동 재정렬하는 로직을 추가하여 거울상 문제를 해결했다.

### 2. 기울어진 라벨의 정방향 정렬
YOLO-OBB 박스의 바운딩 좌표 순서를 상/하/좌/우 길이에 따라 정형화함으로써, 비스듬하게 촬영된 라벨을 반듯한 직사각형 이미지로 잘라내어 Donut에 전달하도록 구성했다.

## 정리

별도의 딥러닝 분류 모델을 추가하지 않고, 전처리단의 좌표 정렬 알고리즘과 데이터 규칙을 정돈하는 것만으로 라벨 정렬 문제를 해결할 수 있었다.

- 합성 데이터 mAP 착시 -> 실제 데이터 혼합 학습으로 해결
- 좌표 유실 이슈 -> Coordinate Clipping 적용
- 크롭 반전 이슈 -> 꼭짓점 좌표 자동 재정렬 로직 구축
