3편에서 파이프라인을 한 바퀴 돌렸을 때 MAPE가 42%로 나왔다. 예전에 같은 데이터로 SARIMA를 돌렸을 땐 17% 정도였던 걸로 기억하는데, 어디서 꼬였는지 세 겹으로 파고든 기록이다.

## 문제 1: 테스트셋이 사실상 1개 포인트였다

마지막 6개월을 테스트셋으로 잡았는데, 실제 값이 `[3428, 0, 0, 0, 0, 0]`이었다. 원본이 특정 시점까지만 실측이고 그 뒤는 "아직 기록 안 됨"이 0으로 채워진 것이다. 평가 함수는 실제값이 0인 달을 나눗셈 문제로 마스킹해 빼는데, 그러면 남는 건 딱 한 달치 오차뿐이다. "6개월 평가"라고 부르고 있었지만 사실상 1개 포인트짜리 지표였던 셈이다.

고침은 이렇다. 시계열 끝에서부터 연속된 0(미기록)을 잘라내고, 그 앞의 "진짜 마지막 실측 시점"을 기준으로 테스트 구간을 잡게 했다.

```python
def trim_trailing_zero_tail(series):
    end = len(series)
    while end > 0 and series.values[end - 1] == 0:
        end -= 1
    return series.iloc[:end]
```

## 문제 2: auto_arima가 추세를 놓친다

테스트셋을 고쳤는데도 MAPE는 40%대에 머물렀다. 확인해보니 `auto_arima`가 차분을 아예 안 한 모델(`ARIMA(0,0,0)(2,0,0)[12]`)을 골랐다. 이 시계열은 몇 년에 걸쳐 뚜렷하게 우상향하는데(2000대에서 3500대로), 차분이 없으면 모델이 그냥 과거 평균 근처로 예측해버린다.

이상한 건, 단위근 검정(KPSS/ADF 등)을 직접 돌려봐도 전부 "d=0, D=0으로 충분하다"고 나왔다는 점이다. 통계적으로 "단위근이 없다"는 것과 "추세가 없다"는 건 다른 얘기라, 이 시리즈처럼 노이즈 대비 추세가 두드러지는 경우엔 단위근 검정만으로 차분 필요성을 못 잡아낸다. 이걸 말로만 알던 걸 실제로 겪었다.

### 해결: d/D를 검정이 아니라 validation 성능으로 고른다

수동으로 order를 박아넣는 대신, d∈{0,1,2} × D∈{0,1} 조합을 전부 학습시켜서 validation 예측 오차(MAPE)로 최적 조합을 고르는 반자동 방식으로 바꿨다. p,q,P,Q는 각 조합 안에서 여전히 auto_arima가 AIC 기준으로 찾는다.

```
d=0 D=0 → valid_mape=35.17
d=0 D=1 → valid_mape=23.79
d=1 D=0 → valid_mape= 3.47
d=1 D=1 → valid_mape= 1.76   ← 선택
d=2 D=0 → valid_mape=18.24
d=2 D=1 → valid_mape=24.12
```

## 문제 3: 골라놓고 refit 했더니 예측이 0으로 붕괴

`d=1, D=1`이 validation에서 제일 좋았으니, 이 설정으로 더 많은 데이터를 넣어 재학습(refit)해서 최종 테스트에 썼다. 그랬더니 예측이 전부 0 근처로 붕괴했다. MAPE 97%.

원인은 표본 크기였다. 계절차분(D=1, 주기 12)까지 겹치면 사실상 1년치를 통째로 잃는데, 월별 데이터가 80~90개뿐이라 표본이 조금만(6개월) 바뀌어도 계절 성분 추정이 완전히 달라진다. 같은 order인데 학습 데이터만 6개월 늘었을 뿐인데 전혀 다른 모델처럼 굴었다.

해결은 refit을 안 하는 것이었다. validation에 썼던 모델(선택 당시 데이터까지만 학습된 상태)을 그대로 재사용하고, 예측 지평선만 늘려서 뒤쪽 test 구간만 최종 평가·서빙에 썼다.

```
[train] test_actual=[   0 3627 3474 3523 3519 3428]
[train] test_pred  =[   0  3082 4016 3150 3190 2937]
[train] metrics={'mae': 380, 'rmse': 424, 'mape': 12.98}
```

MAPE 42%에서 12.98%로. 예전에 봤던 17%와 비슷하거나 오히려 낫다.

## 알아둘 트레이드오프

지금 등록·서빙되는 모델은 refit을 안 했으니 "train+valid+test를 다 뺀" 시점까지의 데이터로만 학습돼 있다. 즉 최신 데이터를 전부 반영한 모델은 아니다. 이건 `model_trained_through` 파라미터로 MLflow에 남겨서 투명하게 확인할 수 있게 해뒀다. 그리고 애초에 이 파이프라인 자체가 데이터가 최신화될 때마다 재학습되는 걸 전제로 하니까, 재학습 시점마다 이 d/D 탐색을 다시 거치면 자연히 해소되는 구조다.

## 다음 편

나머지 스텝(0/1/3)에도 같은 파이프라인을 적용해서, d/D 선택이 스텝마다 다르게 나오는지, 그리고 한 Experiment 안에 여러 모델을 모아 비교하는 게 실제로 되는지 확인한다.
